# 004a · OTP2 local setup (Docker)

## Goal

Run OpenTripPlanner 2 locally via Docker with Barcelona transit data so that the isochrone endpoint is available at `http://localhost:8080` for frontend development. Same Docker setup is used for VPS deployment later.

Prerequisite for: [004-public-transport-isochrone.md](004-public-transport-isochrone.md)

## What you need

- Docker + Docker Compose
- ~2 GB free RAM
- ~1 GB disk for data + built graph

---

## Directory layout

```
backend/
  docker-compose.yml         ← shared across all backend services
  otp/
    data/                    ← mounted to /var/opentripplanner/ inside container
      otp-config.json
      router-config.json
      tmb-gtfs.zip           ← metro L1–L5, L9, L11 + city buses
      fgc-gtfs.zip           ← metro L6–L8, L12 + suburban lines
      rodalies-gtfs.zip      ← commuter trains C1–C10
      barcelona.osm.pbf
      graph.obj              ← generated by build step, gitignored
```

All GTFS filenames **must contain "gtfs"** — OTP skips files without it.

`backend/otp/data/` goes into `.gitignore` (binary data, hundreds of MB).

---

## Step 1 — Create config files

`backend/otp/data/otp-config.json`:
```json
{
  "otpFeatures": {
    "SandboxAPITravelTime": true
  }
}
```

Enables the `/otp/traveltime/isochrone` endpoint — the only OTP2 endpoint that supports transit isochrones.

`backend/otp/data/router-config.json`:
```json
{
  "routingDefaults": {
    "walkSpeed": 1.33,
    "maxTransfers": 0
  }
}
```

---

## Step 2 — Get GTFS data

Three feeds cover the full Barcelona metro network + commuter trains. A download script handles all three.

**TMB requires API credentials** (free registration at developer.tmb.cat). Add them to `backend/.env` (already gitignored):

```
TMB_APP_ID=your_app_id
TMB_APP_KEY=your_app_key
```

Then run:

```bash
bash backend/otp/download-gtfs.sh
```

The script downloads TMB (metro L1–L5, L9, L11 + city buses), FGC (metro L6–L8, L12 + suburban), and Rodalies (commuter trains C1–C10) into `backend/otp/data/`.

All GTFS filenames **must contain "gtfs"** — OTP skips files without it (the script handles this).

---

## Step 3 — Get OSM data (Barcelona bbox only)

Download Catalonia from Geofabrik and cut to Barcelona metro area to keep graph build fast (~20–40 MB instead of 250 MB).

```bash
# Install osmium if not present: brew install osmium-tool

# Download Catalonia (~250 MB)
curl -L -o /tmp/catalonia.osm.pbf \
  https://download.geofabrik.de/europe/spain/catalonia-latest.osm.pbf

# Cut to Barcelona metro area bbox (lng 1.90–2.35, lat 41.25–41.65)
osmium extract \
  --bbox 1.90,41.25,2.35,41.65 \
  --set-bounds \
  -o backend/otp/data/barcelona.osm.pbf \
  /tmp/catalonia.osm.pbf
```

> **Alternative if osmium is a hassle:** download a pre-cut extract directly:
> https://download.bbbike.org/osm/bbbike/Barcelona/ → `Barcelona.osm.pbf`

---

## Step 4 — docker-compose.yml

`backend/docker-compose.yml`:

```yaml
services:
  otp:
    image: docker.io/opentripplanner/opentripplanner:2.5.0_2024-01-02T09-25
    volumes:
      - ./otp/data:/var/opentripplanner
    ports:
      - "8080:8080"
    environment:
      JAVA_TOOL_OPTIONS: "-Xmx2g"
    command: ["--load", "--serve"]
```

---

## Step 5 — Build graph

Run once to build `graph.obj` from OSM + GTFS (takes 2–5 min):

```bash
cd backend
docker compose run --rm otp --build --save
```

---

## Step 6 — Run server

```bash
cd backend
docker compose up
```

Server starts at `http://localhost:8080`. OTP web UI at `http://localhost:8080/otp/`.

---

## Step 7 — Verify

### 7a — Basic transit isochrone

```bash
curl -s "http://localhost:8080/otp/traveltime/isochrone?\
location=41.3874,2.1687\
&time=2025-01-13T09:00:00%2B01:00\
&cutoff=PT30M\
&modes=WALK,TRANSIT" | head -c 500
```

Expected: GeoJSON `FeatureCollection` with a polygon feature.

---

## Done when

Step 7a returns a valid GeoJSON `FeatureCollection` with a `MultiPolygon` feature covering a clearly transit-extended area (significantly larger than walking alone).

**Note on transfer control:** `maxTransfers` is not supported as a per-request parameter in TravelTime Sandbox, and OTP2 2.5.0 has no hard transfer limit in router-config.json. Transfers are discouraged via `transferPenalty: 300` (5 min cost). Two-container approach was considered and rejected due to RAM cost (~2GB). See [004-public-transport-isochrone.md](004-public-transport-isochrone.md) for rationale.
